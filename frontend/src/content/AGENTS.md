# content

## Purpose
Typed local content modules. Each file exports one dataset that `src/lib/cms` reads as the fallback whenever the Laravel CMS API is unreachable, and that the `/admin` console writes back to when an editor saves. They are the offline source of truth for the whole site.

## Key Files
| File | Description |
|------|-------------|
| `projects.ts` | `projectsData: Project[]` — the project archive with full `caseStudy` records (~1.6k lines, the largest file). Regenerated by `scripts/sync-github.mjs`; edit through the `/admin` console rather than by hand |
| `experiments.ts` | `experimentsData: Experiment[]` — lab entries with `objective`, `howItWorks`, `limitations`, `takeaways`, `demoUrl`, `repoUrl` |
| `notes.ts` | `notesData: Note[]` — articles with `content: string[]` paragraphs and an optional `toc: Array<{ id, text, level }>` that is index-aligned with `content` |
| `capabilities.ts` | `capabilitiesData: CapabilityItem[]` — six "what I build" cards with `code`, `iconKey`, and `relatedWorkLink` |
| `experience.ts` | `experienceData: ExperienceItem[]` — timeline entries with `type` (`Work`, `Education`, `Research`, `Community`, `Milestone`), `organization`, `roleAtTime`, and `highlights` |
| `technologies.ts` | `technologiesData: Technology[]` — the toolbox shelf, grouped by the six `TechCategory` values with `featured` and `order` flags |
| `homePage.ts` | `heroData: HeroData`, `marqueeKeywords: string[]`, `manifestoData: ManifestoData` — the three CMS-backed homepage blocks |
| `siteSettings.ts` | `siteSettings: SiteSettings` — global SEO/social copy: `siteTitle`, `ownerName`, `logoText`, `contactEmail`, `resumeUrl`, `contactEyebrow/Heading/Intro`, `journeyEyebrow/Heading/Intro`, `journeyChapters`, `socialLinks`, `seoDefaults` |
| `announcements.ts` | `announcementData: Announcement` — the banner state: `enabled`, `label`, `message`, `linkLabel`, `linkUrl`, `statusType` |

## For AI Agents

### Working In This Directory
- Never rename an export or change its shape. `src/lib/cms/index.ts`, `src/app/admin/actions.ts`, and `src/types/index.ts` all depend on these exact names.
- The admin console rewrites these files as `JSON.stringify(data, null, 2)` inside a typed import header. That means hand-formatting is lost on the next save — edit the data, not the layout.
- The type annotation is the contract: `projectsData: Project[]` must satisfy `Project` in `src/types/index.ts`. Changing a field there means changing the interface and the backend model too.
- `notes.ts` keeps `toc` index-aligned with `content`: `toc[idx]` is the heading that precedes `content[idx]`. Keep the arrays the same length.
- Adding a content type requires four things together: the data file, the interface in `@/types`, the `get*` accessor in `@/lib/cms`, and (if it should be editable) the server action in `src/app/admin/actions.ts`.
- Prefer the `/admin` console or `scripts/sync-github.mjs` for bulk edits.
- `projects.ts` is generated from GitHub metadata; hand edits there are overwritten by the next sync.

### Testing Requirements
- `pnpm typecheck` from the repo root — this is the check that catches a shape mismatch against `@/types`.
- `pnpm build` if you added or renamed a content type, since the CMS accessors and the admin actions are resolved at build.
- Manual in `next dev`: load `/` and each index page with the CMS API stopped, so the local fallback is what renders.

### Common Patterns
- Every file imports its interface from `@/types` and annotates the export: `export const projectsData: Project[] = [...]`.
- IDs are stable slugs (`"cua"`, `"canvas-graph-rag"`, `"cap-1"`, `"exp-2025-present"`) — the admin console and the sync script rely on them.
- `order` fields control sort order in `src/lib/cms`; `index` is a zero-padded display string for projects.

## Dependencies

### Internal
- `@/types` — `Project`, `Experiment`, `Note`, `CapabilityItem`, `ExperienceItem`, `Technology`, `HeroData`, `ManifestoData`, `SiteSettings`, `Announcement`
- `src/lib/cms/index.ts` — reads these as fallbacks
- `src/app/admin/actions.ts` — writes to these files
- `scripts/sync-github.mjs` — regenerates `projects.ts` and patches `homePage.ts`

### External
- None — plain TypeScript modules with no runtime dependency
