# Frontend

## Purpose
Public-facing Next.js 16 App Router portfolio site (neo-brutalist design system, served on :3000). It renders static marketing pages whose content comes from `src/content/*.ts` TypeScript data modules, and can be overridden at request time by the Laravel CMS API at `http://localhost:9000` through the adapter layer in `src/lib/cms`. A PIN-protected local content console lives at `/admin` and writes back into `src/content/*.ts`.

## For AI Agents

### Working In This Directory
- Path alias `@/*` maps to `src/*`; always use `@/` imports, never relative `../../` chains.
- Default to React Server Components. Add `'use client'` only where state, event handlers, or browser APIs are needed — currently `Header`, `ContactContent`, `ToolboxSection`, `ContactSection`, `JourneySection`, `AdminClient`.
- Pages read data exclusively through `@/lib/cms`; never import `@/content/*` or `@/lib/api` from a page or component.
- This is the public site. The separate CMS dashboard is `frontend-admin/` (:3001); the `/admin` route here is only the local PIN console.
- Never edit `node_modules/`, `.next/`, or `next-env.d.ts`.
- Never commit `.env.local`.

### Testing Requirements
- No unit test runner is wired up. The real checks are `pnpm typecheck` (runs `tsc --noEmit`) and `pnpm build` — both from the repo root or from `frontend/` directly.
- Root `pnpm typecheck` typechecks both `frontend` and `frontend-admin`; use `pnpm -C frontend typecheck` to scope to this app.
- `pnpm build` is the only check that exercises `generateStaticParams`, metadata generation, and route wiring.

### Common Patterns
- Content flows: `src/content/*.ts` (local fallback) → `src/lib/cms` (merge with CMS API) → page → `src/components/sections` (props only).
- The CMS API must stay reachable-optional: `src/lib/api.ts` returns `null` on any failure so the site still builds offline against local content.
- Types in `src/types/index.ts` are shared with the Laravel backend — change them in lockstep with the backend models.
