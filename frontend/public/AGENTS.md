# public

## Purpose
Static asset directory. Files placed here are copied verbatim to the site root by Next.js and served without any build processing — `public/og-image.png` is reachable as `/og-image.png`. The directory is currently empty apart from the `.gitkeep` placeholder, so the images referenced by content (the OG card, `resume.pdf`) have to be added here.

## For AI Agents

### Working In This Directory
- Reference assets by absolute URL path (`/og-image.png`), never by importing them from `public/` in code.
- Files here are not processed by the bundler: no hashing, no optimization, no TypeScript. Keep them small and pre-compressed.
- `seoDefaults.ogImage` in `src/content/siteSettings.ts` points at `/og-image.png`; that file does not exist yet — add it here before shipping the OG preview.
- `siteSettings.resumeUrl` points at `/resume.pdf`; same deal.
- Do not add source code, `.ts`/`.tsx` files, or anything that needs transpiling.

### Testing Requirements
- `pnpm typecheck` and `pnpm build` do not validate assets. Check the path resolves by loading the URL in `next dev` (a missing file yields a 404 from the static handler).
- Adding an asset changes no TypeScript, so no typecheck is required — but run `pnpm build` if you also touched code.

### Common Patterns
- One folder, flat. No subdirectories — the deployment serves `public/` as-is.
- Binary assets are committed directly; nothing in this directory is generated by a script.

## Dependencies

### Internal
- `src/content/siteSettings.ts` (`seoDefaults.ogImage`, `resumeUrl`) references assets placed here

### External
- None — served by the Next.js static file handler
